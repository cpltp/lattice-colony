# lattice-colony

**大小不一的方块，如何自己拼成一个形状。**

每个单元只能看见自己的四个邻居。没有任何一个知道"整体应该长什么样"，
它们仍然能拼出圆形、直线、空心方、十字、方块 —— 而且大小可以不一样。

三个互不依赖的算法，加起来不到 200 行。没有调度器，没有地图，没有全局蓝图。

```
[在线演示] demo/index.html
```

## 为什么会有这个仓库

做自组装时翻了一遍现成实现 —— aTAM、Kilobot、各种多边形拼接 ——
它们都建立在一个共同前提上：**所有单元一样大**。

一旦单元尺寸连续可变（比如由外部数据决定的"基因"），三件事同时失效：

| 环节 | 等大时的做法 | 变尺寸后为什么不成立 |
|---|---|---|
| 排布 | `x = gx * pitch` | pitch 是常量，格子不是 → 出现缝或重叠 |
| 落位 | 随便挑一个空位 | 大格子塞进小空位会挤出邻居 |
| 形状 | 给定 N 个单元塞进形状 | 形状能容纳的格数是离散的，N 可能不存在 |

这三段代码就是那个重写结果。各自独立，可以单独拿去用。

## 三个算法

### ① 行列前缀和排布 · `src/layout-prefixsum.js`

```js
import { layoutPrefixSum } from './src/layout-prefixsum.js';

const cells = [
  { gx: 0, gy: 0, w: 30, h: 16 },
  { gx: 1, gy: 0, w: 12, h: 24 },
  // ...
];
const rects = layoutPrefixSum(cells, { cols: 8, rows: 6 });
// → [{ x, y, w, h }, ...]  与输入同序
```

先把每一列最宽的、每一行最高的各自前缀求和，坐标就是两个前缀和的交点。

- **结构性对齐**，不是迭代松弛 —— 所以**零抖动**，跑多少次都一样
- `O(N + COLS + ROWS)`，N=350 时 0.20 ms
- 格子在自己那一列/行里居中，所以窄格子不会贴左边、矮格子不会贴上边

### ② 形状能容纳多少格 · `src/shape-cardinality.js`

反直觉的地方：**约束不在"怎么塞"，而在"每种形状能给出哪些格数"**。

| 形状 | 格数序列 | 想要 14 会得到 |
|---|---|---|
| `line` | 任意 | 14 ✓ |
| `circle` | 1, 5, 13, 29… 但可补壳 | 14 ✓ |
| `square` | 1, 4, 9, 16, 25 | 16 |
| `ring` | 8, 16, 24, 32 | 16 |
| `cross` | 1, 5, 9, 13, 17 | 13 |

所以对 `ring` / `cross` 来说，**"14 个单元拼一个十字"这件事根本不存在**。
这时候要问的不是"怎么把 14 塞进去"，而是"这个形状现在能容纳多少"。

### ③ 黏附 + 空间双收益落位 · `src/placement-score.js`

```js
import { pickSlot } from './src/placement-score.js';

const best = pickSlot(candidates, occupied, {
  bondGain: 1.0,    // 贴上去之后四邻同类越多越好   → 抱团
  spaceGain: 0.15,  // 那个格子四邻空着的越多越好   → 不挤
  cols: 20, rows: 14,
});
```

落位偏好的来历是**接触抑制**（contact inhibition）：细胞挨着就停止分裂，
一旦旁边空出来了，抑制消失，它就顺势铺过去。

细胞不是"知道那里缺了一块"，是它自己旁边空出来了。

**两个权重的比值是连续难度旋钮，不是开关：**

| 配置 | 长出来的形状 |
|---|---|
| `bond 1.0 / space 0.0` | 5×5 紧凑团块 |
| `bond 0.6 / space 1.1` | 8×7，有分支 |
| `bond 0.2 / space 1.1` | 8×7，铺开成网 |

偏空间会主动铺进缺口，偏黏附则只肯贴着同类挤。
于是"缺口补不补得上"取决于还有没有个体愿意挪过去 —— 而不是某个调度器的决定。

## 注意

这三个模块是**从具体项目里抽出来的**，不是先设计后实现。
它们解决的是一组特定的问题，换到别的场景可能需要调整。已知的取舍：

- `layoutPrefixSum` 假设格子轴对齐、不旋转
- `shape-cardinality` 的 `circle` 靠"补壳"填中间值，补出来的格子按到圆心距离排序
  —— 所以圆的边缘在大半径下会有点毛糙，这是离散化的必然结果，不是 bug
- `placement-score` 只看四邻域。要看更远（比如半径 2 的密度）得自己扩展
