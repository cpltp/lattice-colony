大小不一的方块
如何自己拼成一个形状

每个单元只能看见自己的四个邻居，没有任何一个知道"整体应该长什么样"。 它们仍然能拼出圆形、直线、空心方、十字、方块 —— 而且大小可以不一样。

看演示 读算法

① 变尺寸排布

同一行/列里格子大小不同，前缀和让它们紧贴，不留缝也不重叠。

② 形状的离散格数

空心方只能给 8/16/24/32…，十字只能给 4a+1。拖数量看形状怎么跳。

③ 落位偏好

黏附收益（抱团）vs 空间收益（不挤）。调权重看它往哪长。

三个算法

都只依赖局部信息。没有调度器，没有地图。

① 行列前缀和排布

先把每一列的最宽、每一行的最高各自前缀求和，坐标就是两个前缀和的交点。 结构性对齐，不是迭代松弛，所以零抖动。 已知的多边形/机器人自组装实现都假设单元等大，这条是为变尺寸写的。

② 形状的离散格数

不是"给定 N 塞进形状"，而是先知道 每种形状能给出哪些格数。 空心方卡死在 8r、十字卡死在 4a+1； 圆和直线则可以通过补壳/截断命中任意值。

③ 黏附 + 空间双收益

落位时算两笔账：贴上去之后同类多不多、那个格子旁边空不空。 两个权重的比值是连续难度旋钮 —— 偏空间会主动铺进缺口，偏黏附则只肯贴着同类挤。

排布：两个前缀和

每个格子的大小由外部数据决定，所以列与列的宽度不一样。 不能简单乘格距 —— 那样相邻方块之间会出现缝。 

// 每列最宽、每行最高
for (const c of cells) {
  colW[c.gx] = max(colW[c.gx], c.w);
  rowH[c.gy] = max(rowH[c.gy], c.h);
}

// 前缀和 = 该列左边缘 / 该行上边缘
let acc = 0;
for (let x = 0; x < cols; x++) {
  colK[x] = acc; acc += colW[x];
}

// 坐标 = 前缀和 + 本格的一半
x = colK[c.gx] + colW[c.gx] / 2;
y = rowK[c.gy] + rowH[c.gy] / 2;
为什么值得单独拆出来

变尺寸，是个被跳过的前提

aTAM、Kilobot，以及大多数多边形自组装实现，都建立在"所有单元一样大"之上。 一旦单元尺寸连续可变，排布、落位、形状匹配三件事都要重写。 这三段代码就是那个重写结果 —— 各自独立，可以单独拿去用。
